Intelligent Remote Sensing Analyst

Task planning— Data optimisation— Model optimisation— Evaluation— Experience update

As remote sensing data spreads across more platforms, more modalities and more tasks, the old pattern — a fixed model plus manual tuning — stops keeping up. Data preparation, model selection, parameter tuning and result analysis still lean heavily on human expertise, and that is what caps how autonomous a system can be. The Intelligent Remote Sensing Analyst turns interpretation from single-model inference into a closed loop run by several specialised agents working together.

The core goal A system that reads its own results and decides, on its own, whether the next thing to improve is the data — or the model.

Perception & reasoning

One analyst across every source

Optical, SAR and infrared imagery, from satellites and from UAVs, read by a single model — and reasoned about, not just recognised.

Built on a self-collected dataset of over three million image–text pairs, the system handles object detection, visual question answering, relation reasoning, instruction decomposition, action decision and task planning. On harder tasks it reaches for outside help on its own — calling a visual grounding tool for a target's position, then decoding a route from it — closing the path from understanding a task, through spatial reasoning, to generating the action.

Division of labour

Four agents, one loop

On top of that perception layer sit four agents, each owning the part of the job an algorithm engineer would otherwise do by hand — three that do the work, and one that judges it.

Main agent
Reads the task, breaks it into a workflow, and decides which agent runs when.
Data agent
Cleaning, tiling, class statistics, sample balancing and augmentation — everything that decides what the model actually gets to learn from.
Vision agent
Builds and trains models, tunes them, swaps architectures, and combines them when two turn out to be complementary.
Critic agent
Error analysis, bottleneck localisation, and concrete proposals for what to try next — kept independent of the three agents whose work it judges.

Alongside them sits the experience module: not an agent, but the memory the agents share. It accumulates outside knowledge and past experimental results, and hands them forward as priors for the next task.

The analyst does more than run existing models. When results come back weak — long-tail categories, targets with barely any samples — it works out where the bottleneck actually lives. The data agent looks first: class distribution, sample quality, then augmentation, class balancing and few-shot organisation of what little data exists. If that is not where the ceiling is, the search moves to the vision agent, which goes looking for a better architecture, a better training strategy, or a better combination.

Find the problem→ Locate the cause→ Choose the search space→ Run the experiment→ Update the strategy↶

The last step feeds the first — the loop does not terminate, it converges.

Case study

From spotting a few-shot problem to optimising the detector

Fine-grained aircraft detection on FAIR1M. What the system receives is not a hand-built pipeline — it is a goal: identify the aircraft, analyse detection performance, propose improvements, and keep raising accuracy.

01
Data agent

Finding the long tail on its own

The main agent decomposes the workflow. The data agent then writes its own data-processing scripts — filtering aircraft categories, building the train and test splits, tallying the class distribution — and flags that types such as C919 and ARJ21 have far fewer samples than the rest, raising a long-tail and few-shot warning before a single model has been trained.

02
Vision agent + Critic agent

Baseline first, then a diagnosis

With the data ready, the vision agent builds and trains a baseline and reports overall accuracy alongside per-class performance. The critic agent takes the weak classes apart, proposes why they are weak, and generates candidate remedies — augmentation, a larger model, few-shot learning. Each candidate goes into automated trials; results decide what survives.

03
Vision agent

When data runs out of room, move to the model

Once data and training tweaks approach their ceiling, the search space shifts from the data layer to the model layer. The vision agent runs fast comparative trials across candidate models and keeps the stronger ones. Seeing that different models are strong on different classes, it then generates ensemble strategies — and where the user asks for it, writes scripts to modify the architecture itself.

Which puts the whole optimisation on a ladder that climbs one rung at a time:

Augmentation→ Few-shot strategy→ Model swap→ Model search→ Ensembling→ Architecture surgery

Data space Model space

The point is not running every method in order. It is that the last round's evidence decides which space the next round enters.

Self-evolution

Evaluation is what drives the loop

Self-evolution rests on two things: judgement that stays independent, and decisions that stay dynamic.

The critic agent keeps deciding which strategies are working, which should be dropped, and whether the next round belongs in the data space or the model space — then routes that diagnosis back to the main, data and vision agents. What comes out is a loop that keeps turning: data analysis → training → error diagnosis → strategy generation → experimental validation → diagnosis again.

Meanwhile the successful strategies, the dead ends and the bottlenecks are all written down. Combined with outside knowledge from published papers and open-source implementations, they widen the space of things worth trying. Faced with a similar task later, the system reuses what worked and steps around what has already been proven not to — task execution, experience, updated strategy, and capability that grows.

A failed experiment stops being a failure. It becomes the input to the next decision.

In short

From model intelligence to system-level autonomy

The point of the Intelligent Remote Sensing Analyst was never to build a larger remote sensing model. It is that the work an algorithm expert used to do — analysing the task, preparing the data, optimising the model, evaluating the experiment, accumulating the experience — is handed, piece by piece, to agents. Six abilities, and the two research efforts behind them:

Perception & reasoning
See
Read multi-platform, multi-modal remote sensing data
Think
Analyse how targets relate; make sense of a complex task
Act
Call tools on its own, decide, and plan what happens next
Self-evolution
Reflect
Find the errors, and the bottleneck actually holding performance back
Learn
Draw on outside knowledge and on its own history to find a new route
Evolve
Turn every task into experience for the task after it

From perception to cognition, from cognition to action. From carrying out a task to reflecting on it — and from reflection to evolving on its own.

We used to hand the model an image. Before long, we may only need to hand the agent a task.
